How the Kite ticker, the workers, the SSE watchers and the Signal matrix stay in sync when several people watch different instruments at once — what guarantees that, what it costs in latency, and where it still runs out of room.

01 · The path

One tick, end to end

Every window is an SSE reader on a Redis key. Nothing computes in the request path: the browser reads cache, and a worker fills it. The instrument travels the whole way down as part of every key — that is the single idea the whole design rests on.

The one number that decides everything

A Signal row build is sequential and unmeasured. At ~2 s a row, a 10-second pass serves about five rows, so ten watched instruments refresh roughly every other pass — around 30 seconds each, not 125 ms. Measure this before promising anyone a refresh rate.

04 · What was broken

Three collisions, all the same shape

Each bug was a key that named a tenant but not an instrument, so the second window overwrote the first. Toggle each card to see the before and after.

Two Lab windows fought over one ticker subscription

The hub replaces a source's whole token map. Both Lab windows synced under the same source name, so every tick NIFTY's chain unsubscribed SENSEX's and back — both windows flapping to REST. Found only when the scenario changed from Lab+Signal to Lab+Lab.

beforesources["options_lab"] = { … } ← last writer wins
aftersources["options_lab:NSE:NIFTY 50"] + sources["options_lab:BSE:SENSEX"] → unioned

Param Chart moved the desk for everyone

Opening a chart for an instrument issued a tenant-wide config PATCH, and the month pack key had no instrument in it. Ten admin screens overwrote one another and dragged Signal's desk primary along.

beforepack:1D:2026-08 · client PATCHes tenant config
afterpack:NSE:NIFTY 50:1D:2026-08 · instrument rides ?underlying=

Signal starved every unpinned instrument

The worker warmed two extra rows, pinned names first — so RELIANCE behind three pinned indices never got a row, and the stream quietly served the desk primary's numbers under RELIANCE's heading.

05 · Guarantees

What each layer promises

Kite ticker hub real time · 1 socket / tenant
  • One WebSocket per tenant regardless of how many windows are open.
  • Each tool owns named sources; the hub unions them and sends only the delta.
  • Closing a window prunes just that instrument's source — never another tool's.
  • Refuses to start when WEB_CONCURRENCY > 1.
Workers 125 ms tick · bounded fan-out
  • Lab: one refresh per watched instrument, at most 3 concurrently.
  • Signal: rows in rotation inside a 10 s budget; the cursor resumes where the last pass stopped, so the tail is never starved.
  • Param Chart: one overlay per (tenant, instrument), plus per-instrument rebuild locks.
  • A failure on one instrument no longer cancels the rest of the tick.
Redis every key carries the instrument
  • Watch keys are {tenant}|{instrument} with a 45 s TTL — self-cleaning.
  • Signal splits shared globals from per-instrument row. Globals are written once per warm cycle, not once computed — every row build still produces them, and the metric tier caches absorb the repeat.
  • Lab snapshots are fingerprinted by underlying and wings.
SSE readers 125 ms · cache only
  • Never computes and never opens Postgres in the steady state.
  • Identical frames send a keepalive instead, so React does not re-render at 8 Hz.
  • An instrument with no row yet gets a warming frame under its own name — never another instrument's numbers.
Browser one tool per window
  • The shared instrument board is sessionStorage + a DOM event — per tab, so separate tabs never cross-talk.
  • The instrument lives in the URL and rides every request as a query parameter.

06 · Standing limits

Things you did not ask about, and should know

Rotation is not simultaneity

Ten watched Signal rows are served in rotation, not all at once. Every row is served; not every row is equally fresh at any instant. A row that waited a pass shows its age badge — that is correct behaviour, not a fault.

Single process is a hard ceiling

WEB_CONCURRENCY=1, and the hub refuses to run otherwise. Every in-process cache assumes it too. This work made the ceiling behave well under load; it did not raise it. Raising it means moving the hub out of the web process.

Old chart packs are orphaned

The Param Chart key shape changed, so cached packs from before the deploy are unreachable. The first open per instrument rebuilds from Kite and may show the “still rebuilding” notice. One-time cost, no data loss.

Not yet proven against live Kite

The tests prove the keying, budgets and pruning. They do not prove Kite's rate limits hold at ten-window fan-out. Watch options_lab_yield_to_signal and signal_matrix_pass_budget_spent on first real use.
